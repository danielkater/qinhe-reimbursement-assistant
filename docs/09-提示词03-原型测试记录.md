# 提示词 03：裸问答原型测试记录

**测试时间：** 2026-11-05。**大模型：** DeepSeek `deepseek-flash`，温度 0。**嵌入模型：** 本地 `BAAI/bge-small-zh-v1.5`。**依据门槛：** 相似度 0.59。

下面的回答都是模型的实际输出，未经修改。

## 一、结论：关闭防护时，模型有没有编？

**有，但不是编数字，而是把制度没写的事项说成了确定结论。**

| 问题 | 关闭防护 | 是否有问题 | 开启防护 |
| --- | --- | --- | --- |
| 上海住酒店一晚最多报多少？ | 600 元 | 正确 | 正确，引用第 2 条 |
| 发票丢了怎么办？ | 第 13 条的处理办法 | 正确 | 正确，引用第 13 条 |
| 报销时限是多久？ | 30 日、90 日的规定 | 正确 | 正确，引用第 8 条 |
| 健身卡可以报销吗？ | **断言“不可以”** | **越界推断** | 转人工（第一关） |
| 公司年假有几天？ | 说制度里没有 | 没有编 | 转人工（第一关） |
| 酒店的按摩费能报吗？ | **断言“不能报销”** | **越界推断** | 转人工（第一关） |
| 出差能报销按摩费吗（补测） | **断言“不能报销”** | **越界推断** | 转人工（第二关） |
| 手机话费每月能报多少（补测） | 说制度里没有 | 没有编 | 转人工（第二关） |

**具体表现：**

- **没有编金额和条款号。** 有依据的 3 题，回答和条款一致。
- **5 道无依据的题，3 道给了确定结论。** 模型自己判断健身卡、按摩费属于“个人消费”，再套用第 12 条。第 12 条没有列出这些项目，而第 15 条写明“本制度未涉及的事项，请转人工咨询，不得自行类推”。员工如果照此理解，可能少报本来能报的费用。
- **引文不完全是原文。** 模型写的“娱乐及其他个人消费不予报销”是把第 12 条拼接后放进引号，第 12 条原文中间还有其他项目。
- **开启防护后，这 5 题全部转人工。** 3 题被相似度门槛拦下，没有调用模型；2 题通过门槛后，由模型判定条款不足。

**这次样本只有 8 题，每题在最终版本上各跑一次，不能代表整体比例。**

## 二、运行方式

```powershell
# 开启防护（默认），无依据时拒答并转人工
python scripts/ask.py

# 关闭防护，观察模型会不会编
python scripts/ask.py --mode guard-off

# 只问一个问题
python scripts/ask.py --mode guard-on -q "发票丢了怎么办？"
```

| 验证项 | 方法 | 结果 |

| Markdown 与 YAML 一致 | 解析后逐字段比较（有测试） | 15 条完全一致 |

### 依据门槛的校准

只用 `examples/eval_questions.yaml` 校准，`holdout_questions.yaml` 没有参与调参。

| 样本 | 可回答题：依据在 top3 | 可回答题：通过门槛 | 无依据题：调用模型前已拦下 |
| --- | --- | --- | --- |
| 校准样本 | 19/20 | 20/20 | 6/8 |
| 留出样本 | 18/20 | **15/20** | 8/10 |

这张表只统计检索和门槛，没有调用模型，所以不是最终回答的准确率。

**这项结果不理想：**

- **相似度分不开有依据和无依据。** 校准样本里，可回答题的最低相似度是 0.601，无依据题的最高相似度是 0.652，两者有重叠。门槛只能拦下明显无关的问题，其余要靠后两关。
- **门槛在新问题上偏严。** 留出样本有 5 道可回答的题被挡下，它们会转人工（偏安全，但覆盖率下降）。
- **检索也有漏。** “报销款什么时候到账”“地铁票要发票吗”“可以预支差旅费吗”的依据不在 top3。

## 五、DeepSeek 与嵌入模型

**DeepSeek 没有 embedding 接口。** 2026-11-05 实测 `/embeddings` 和 `/v1/embeddings` 都返回 404，`/models` 只列出 `deepseek-flash` 和 `deepseek-v4-pro`。

默认的本地模型这次下载成功（占用约 91 MB），无需额外的 API Key。**以后下载失败时的备选方案：**

| 方案 | 做法 | 影响 |
| --- | --- | --- |
| 镜像站 | 设置环境变量 `HF_ENDPOINT` 指向可用的镜像 | 无 |
| 手动放置 | 在能联网的机器下载后，复制到 `storage/models` | 无 |
| 只用 BM25 | 把 `embedding.provider` 设为 `none` | 关闭防护时只用 BM25，开启防护时走关键词规则 |
| 在线嵌入服务 | 设为 `openai_compatible`，并配置 `EMBEDDING_API_KEY` | **问题会多发给一家外部服务，属于数据外发，要先经你确认** |

## 六、决策记录

| 编号 | 决定 | 理由 |
| --- | --- | --- |
| X3 | 按条款切片，单片不超过 500 字，与原文“按 500 字切片”不同 | 条款大多不到 100 字，按字数切会把多条混在一起，无法引用到条款 |
| R14 | 依据门槛定为 0.59，不加查询前缀 | 校准样本的可回答题都能通过；前缀没有改善区分度 |
| R15 | “关闭防护”只关问答防护，查单请求仍在本地拦下 | 数据外发是项目边界，不随实验模式放宽 |
| R16 | 原型每次启动时重建 FAISS 索引，不存盘 | 只有 15 条，重建很快；阶段 3 发布制度时再存盘 |
| R17 | 开启防护时，向量模型或大模型不可用就走关键词规则，不用 BM25 结果作答 | 与架构方案写的“只用 BM25”不同。BM25 总会返回结果，判断不了有没有依据 |
| R18 | 回答未通过校验时，退回关键词规则，而不是摘录 top3 | top3 可能和问题无关，关键词规则更严格 |
| R19 | 校验时跳过行首的列表序号 | 否则“1. 2. 3.”会被当成编造的数字。Streamlit 页面共用这个校验，只会减少误判，不放宽金额检查 |

## 七、已知局限和后续改进

以下问题已知，这一步不修。

| # | 局限 | 影响 | 后续改进 |
| --- | --- | --- | --- |
| 1 | **相似度门槛区分度不足。** 有依据和无依据的问题相似度有重叠，门槛 0.59 在留出样本上只放行 15/20 道可回答的题 | 部分可回答的问题会转人工，偏安全，但覆盖率下降 | 用更大的样本重新校准；比较加入重排或 BM25 信号后的效果 |
| 2 | **第二关依赖模型判断。** 5 道无依据题中有 2 题靠模型判定条款不足，不是代码强制的。样本太少，不足以证明总能拒答 | 还不能证明验收要求的“无依据 100% 转人工” | 用更多近似问题测试；达不到要求就打开严格模式 `strict_unknown_terms`，或增加代码规则 |
| 3 | **有一次失败没能复现。** 第一轮“发票丢了怎么办？”开启防护后未通过校验，退回关键词检索，答案仍然正确。修复前又调用 7 次，修复后的最终运行 1 次，都通过了。当时没有保存模型原文，**不能确定原因**。校验会误伤列表序号是确认过的缺陷，已修复，但不能断定就是那次失败的原因 | 少数回答可能被误判，退回摘录条款原文 | 测试时保存校验失败的模型原文，复现后再判断 |
| 4 | **10 道验收样本题还没跑。** 它们属于架构方案第一周的第 7 天，这一步只做了 3 + 3 对比和 2 道补测 | 验收标准中的“10 道样本题答对”尚未验证 | 新写 6 道有依据、4 道无依据的样本题，并运行评估 |

另外，温度为 0 时输出仍有波动：同一问题的措辞在两轮运行之间有变化，防护结果也可能变化。所以单次结果不能代表整体比例。
